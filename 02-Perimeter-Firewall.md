# 02. Perimeter Firewall (pfSense)

The pfSense firewall serves as the perimeter security gateway for the lab. It handles all routing between the external WAN and the internal LAN, manages NAT rules, and acts as the primary DNS resolver for the enterprise.

## 1. System & Interface Overview
pfSense is deployed as a virtual machine in VMware. It acts as the default gateway for all internal devices.

## 2. NAT & Port Forwarding
To simulate a real enterprise environment where internal services are exposed to the internet, specific port forwarding rules were created on the WAN interface. The attacker cannot directly reach the LAN network; they must target these exposed ports.

<p align="center">
<img width="1182" height="326" alt="NAT Port Forwarding Rules" src="https://github.com/user-attachments/assets/b2da8e0f-8041-43bf-9caf-26e979fc44ef" />
  <br>
  <i>Figure 2: NAT Port Forwarding rules exposing Splunk and Windows 10</i>
</p>

*   **Rule 1 (Splunk Web UI):** Forwarding WAN TCP port `8000` to the Splunk Server (`192.168.1.50:8000`). This allows the host machine to access the SIEM dashboard without exposing the entire LAN.
*   **Rule 2 (Target Endpoint):** Forwarding WAN TCP port `3389` to the Windows 10 Client (`192.168.1.30:3389`). This simulates an exposed RDP service, which will be targeted by the attacker in the Kali brute-force simulation.

---

## 3. Firewall Rules (WAN)
The WAN firewall rules dictate what traffic is allowed into the perimeter from the external network. By default, pfSense blocks all incoming traffic unless explicitly allowed.

<p align="center">
<img width="1160" height="427" alt="WAN Firewall Rules" src="https://github.com/user-attachments/assets/a90c2cae-7da8-40bd-9233-8ff001319539" />
  <br>
  <i>Figure 3: WAN Firewall Rules allowing specific traffic</i>
</p>

*   **Anti-Lockout Rule:** Allows traffic on ports 80-443 to the WAN address for administrative access.
*   **NAT Rules:** The rules for ports `8000` and `3389` were automatically generated by the Port Forwarding configuration in the previous step.
*   **Bogon Networks:** The block rule at the top drops spoofed or unrouteable internet traffic.

## 4. DNS Resolver & Domain Overrides
To ensure the internal machines have internet access independently of the Active Directory server, pfSense is configured as the primary DNS resolver. 

### Enable Forwarding Mode
Forwarding Mode is enabled so pfSense forwards public internet queries (like `google.com`) to upstream DNS servers.

<img width="1169" height="366" alt="Enable Forwarding Mode" src="https://github.com/user-attachments/assets/968fabd5-1abe-4436-9f61-180b4e7a11f2" />

*(Caption: Figure 4: pfSense DNS Resolver configured with Forwarding Mode)*

### Domain Override
Because pfSense is the primary DNS server for the LAN, it must know how to route traffic meant for the internal `soc.lab` domain. A Domain Override was created so that any request for `soc.lab` bypasses public DNS and is sent directly to the Domain Controller (`192.168.1.10`).
