# 04. Active Directory Environment

The Active Directory Domain Controller (DC) acts as the central identity provider for the lab. It is the backbone for simulating an enterprise environment, allowing for realistic user authentication, Group Policy application, and domain-based attacks.

## 1. Domain Controller Setup
The DC is hosted on a Windows Server 2022 VM with a static IP (`192.168.1.10`). 
*   **Domain Name:** `soc.lab`
*   **Hostname:** `DC-01`
*   **Services:** AD DS, DNS, Splunk Universal Forwarder.

## 2. Environment Population (BadBlood)
An empty Active Directory environment does not generate enough telemetry to simulate a real enterprise. To populate the domain with realistic objects, the **BadBlood** tool was executed. 

BadBlood creates a massive, interconnected web of users, groups, and computers, which provides excellent data for threat hunting. As seen in Figure 1, it generated specific Organizational Units (OUs) such as `Tier 1`, `Tier 2`, and `Grouper-Groups`.

## 4. Telemetry (Splunk Universal Forwarder)
To ensure the SOC Analyst can monitor authentication events (like successful logins, failed logins, and Kerberos ticket requests), a Splunk Universal Forwarder was installed on the Domain Controller.

*(Note: The configuration for the DC's Forwarder (`inputs.conf` and `outputs.conf`) is identical to the Windows 10 endpoint, which is documented in detail on the [SIEM page](03-SIEM-Splunk.md)).*
