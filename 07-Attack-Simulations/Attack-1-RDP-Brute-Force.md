# Attack 1: External RDP Brute Force

## 📋 Incident Overview
*   **Tool:** Hydra 
*   **MITRE ATT&CK ID:** [T1110.001 - Brute Force: Password Guessing](https://attack.mitre.org/techniques/T1110/001/)
*   **Target:** Windows 10 Endpoint (`192.168.1.30`) via pfSense WAN (`192.168.80.133`)
*   **Severity:** High (Potential for domain compromise)
*   **Attacker IP:** `192.168.80.1` (Kali Linux routing through the host)

---

## 1. The Scenario
An external attacker on the WAN network identified an exposed RDP port (3389) on the pfSense firewall and launched an automated dictionary attack against the `Administrator` account to gain initial access to the internal network.

## 2. Attack Execution (Kali Linux)
Using Hydra, the attacker targeted the pfSense WAN IP, which NAT-forwarded the traffic to the Windows 10 machine. Hydra cycled through the `rockyou.txt` wordlist, attempting hundreds of passwords per minute.

## 3. Raw Telemetry Evidence of potential attack)
While a single failed login (Event ID 4625) is normal, a high-volume burst of them from a single external IP is a clear indicator of compromise (IoC). 

Here is the raw Windows Event Log generated by the attack:

```text
LogName=Security
EventCode=4625
ComputerName=Win10-SPLUNK-CLIENT.soc.lab
Keywords=Audit Failure
Message=An account failed to log on.

Logon Type:			3

Account For Which Logon Failed:
	Account Name:		Administrator

Failure Information:
	Failure Reason:		Unknown user name or bad password.
	Status:			0xC000006D
	Sub Status:		0xC000006A

Network Information:
	Workstation Name:	kali
	Source Network Address:	192.168.80.1

Detailed Authentication Information:
	Logon Process:		NtLmSsp 
	Authentication Package:	NTLM
```

## 🕵️ Analyst Breakdown of the Log:
* `Logon Type: 3`: This proves the login attempt is coming over the network, not a physical keyboard attached to the machine.

* `Workstation Name: kali`: The attacker's machine name is explicitly leaked in the NTLM authentication attempt.

* `Source Network Address: 192.168.80.1`: Confirms the attack is originating from the external WAN network.

* `Sub Status: 0xC000006A`: Indicates "User name is correct but the password is wrong." The attacker found a valid account (`Administrator`) but is guessing passwords.

* `Authentication Package: NTLM`: RDP uses NTLM for initial authentication.

---

## 4. Automated Defense (CrowdSec IPS)
Within seconds of the attack starting, the CrowdSec Engine parsed the Windows Security logs, recognized the `crowdsecurity/windows-bf` (brute-force) pattern, and triggered a 4-hour ban. The Windows Firewall Bouncer immediately injected a DROP rule into the Windows Firewall, severing the attacker's connection.

## 5. Splunk Detection & Threat Hunting
The SOC Analyst can use Splunk to visualize the attack. The Universal Forwarder successfully shipped both the Windows Security logs and the CrowdSec engine logs to the SIEM.

## Detection Query (SPL)
To aggregate the failed logins and identify the top attacking IPs:

```
index=winlog_clients EventCode=4625
| stats count as Failed_Attempts by Account_Name, Source_Network_Address
| where Failed_Attempts >= 5
| sort - Failed_Attempts
```

## 6. Reporting & Lessons Learned
* **The Outcome:** The attack was successfully mitigated by CrowdSec before a successful login could occur.

* **Security Gap Identified:** RDP should never be directly exposed to the WAN. In a production environment, RDP access should require a VPN connection or be placed behind a Zero Trust Network Access (ZTNA) solution.

* **SIEM Note:** Because this lab utilizes the Splunk Free license, scheduled alerting is disabled. In an enterprise environment, the SPL query above would be saved as a scheduled alert to notify the SOC team via email or ticketing system (like ServiceNow or TheHive).
